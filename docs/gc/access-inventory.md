# Native GC access inventory

`python3 tools/gc_access_inventory.py` regenerates `access-inventory.json`.
`--check` fails if the indexed sources changed. The index groups all candidates
by source file, function and access category, with exact line numbers and source
SHA-256. It intentionally includes stack and static memory instructions as well
as heap instructions. It is an audit navigation aid, not an automated proof of
barrier coverage; full value-provenance classification remains open.

The PE and Mach-O writers produce images, not object field code. Mach-O now
includes GOT, eager bindings, symbol tables and signature coverage for imports.
These layouts have dedicated structural tests; actual loader behavior, worker
imports, TLS and wait/wake still require a separate target/OS audit.
The Linux/Windows/macOS emitters are indexed; their presence does not establish
runtime startup integration or the common context's lifecycle contract.

## Known audit limitations

The scanner indexes current instruction/helper spellings and emitted C/LLVM
statements; it is not a Rust/C parser or a pointer-provenance analysis. Adding a
new memory instruction spelling requires updating its rules. Multiline emitted
statements are indexed at their emission/ABI-reference lines. Enclosing function
names are navigation hints; source line numbers and hashes are authoritative.
The lifetime emitter's private metadata-expression builder is indexed at both
its machine-memory lowering and its expression construction calls; these are
conservative candidates, not a proof of the expression's runtime provenance.
The Task 0 exhaustive semantic inventory/review gate remains open until each
candidate is classified, including indirect helpers, data/static root builders,
and all native boundary lifetimes. A short list of funnels alone is insufficient.

## Source discovery

The inventory discovers all Rust sources under `klassic-native/src` and
`klassic-runtime/src`, and all C sources and headers under `runtime/gc`, in
stable path order. This includes test fixtures deliberately: file presence and
candidate counts are not production integration evidence. Each source receives
a content hash even when no access pattern matches. New helper files therefore
invalidate `--check` without requiring an allowlist update. The matcher remains
a conservative lexical index, not a proof of complete access classification.
