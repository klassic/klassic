## Klassic 0.8.1

Klassic 0.8.1 comes from using the language rather than working on it:
writing the kind of small command-line program people actually write, and
fixing what got in the way. It also removes a debug line that should never
have been in 0.8.0.

### The debug line

`klassic build` printed `DBG unsupported_recursive_inline: <name>` to
standard error whenever a program reached that path. It was left in while
tracking down a compiler hang and shipped in 0.8.0. It is gone.

### The stdlib, where it was wrong

- **`words()` splits on any whitespace.** It only split on `" "`, so
  "fox\nthe" came back as one word -- and the cookbook already described it
  as splitting on whitespace. Anything with more than one line was counted
  wrongly.
- **Map entries have names.** `toPairs()` / `entries()` handed back
  two-element lists, so reading one meant `head(tail(pair))` and typing one
  was impossible: a list holding a String and an Int at once has no element
  type, which is why `at(pair, 1)` failed with "at expects a string". They
  are `MapEntry` records now, read as `.key` and `.value`. **This changes
  the shape of what those two functions return.**

### Diagnostics that say what to do

- **The recursion wall names its cause.** "native recursive function
  requiring call-site inlining" told you nothing actionable. It now reads,
  for example, "a recursive `showAll`, which would have to be compiled at
  each call site because this backend cannot pass `es` (`List<Entry>`) by
  itself" -- naming the parameter, its type, or the missing annotation,
  which is usually the fix.
- **A missing import is a missing import.** The evaluator loads every
  stdlib module, so `"a b".words()` runs; a native build only sees what was
  imported, and rejected the same source with "no method or field `words`
  on String". The message now adds that `std.string` defines a `words`, so
  the receiver's type and the missing `import` are both in view.

### Command-line programs on Apple Silicon

Four of the six cookbook recipes built on x86-64 and one on arm64. Now all
four build on all three targets, because the arm64 backend gained the
pieces they are made of: `foreach` over a list or set, `CommandLine#args()`,
`String#parseInt`, `Process#exit`, and `StandardInput#lines()`.

The two that still do not build anywhere are honest about it: word-count
needs `Map#empty`/`Map#put` in a native build, and config-env needs an
environment lookup whose key is not a literal.
